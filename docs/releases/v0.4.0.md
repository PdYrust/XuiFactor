# XuiFactor v0.4.0

## Highlights

- First stable XuiFactor release after the v0.3 beta series.
- Stable package and release metadata use v0.4.0 names without a beta suffix.
- Documentation is polished around install, update, service lifecycle, policy precedence, explain/status/report/audit, cleanup, and reconcile workflows.
- GitHub issue templates now collect clear operator details for bugs, feature requests, installation/update problems, configuration/server environment issues, documentation issues, and support requests.

## Package Names

```text
xui-factor_v0.4.0_linux_amd64.tar.gz
xui-factor_v0.4.0_linux_arm64.tar.gz
```

Use the archive that matches the server architecture.

## Install

```sh
tar -xzf xui-factor_v0.4.0_linux_amd64.tar.gz
cd xui-factor_v0.4.0_linux_amd64
sudo ./scripts/install.sh
```

Use `scripts/update.sh` from the extracted package when upgrading an existing installation. On systemd hosts, install enables and starts `xui-factor.service` by default, and update enables and restarts it by default.

## Operator Checks

After installing or upgrading, run:

```sh
xui-factor doctor
xui-factor status
xui-factor report
xui-factor reconcile --dry-run
xui-factor cleanup --dry-run
```

Use `systemctl status xui-factor.service --no-pager` to confirm daemon state on systemd hosts.

## Policy Model

XuiFactor resolves one effective decision per client:

```text
exclude > override > single-user rule > inbound scope > global scope
```

Disabling rules or removing policies does not revert previously factored traffic. Removing an exclude or override resumes future matching from current counters and does not retroactively factor earlier traffic.

## Safety

- XuiFactor does not modify 3x-ui source code.
- XuiFactor metadata lives in `xui_factor_*` tables.
- Read-only commands such as `status`, `explain`, `report`, `audit`, and `doctor` do not modify traffic counters.
- Cleanup and reconcile operate only on XuiFactor metadata and do not subtract previously factored traffic.
- Installer and uninstall scripts preserve `/etc/x-ui/x-ui.db`.
