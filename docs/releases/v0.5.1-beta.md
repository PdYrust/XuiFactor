# XuiFactor v0.5.1-beta

## Master and Node Panels

- Install XuiFactor on the 3x-ui master only. The master adds each node's counter deltas to its own client rows, so XuiFactor there factors local and node traffic exactly once, and nodes enforce quotas with the factored totals the master pushes back.
- On a panel managed by a master, ticks are refused, because factoring there as well would multiply node traffic twice. `doctor` reports the role as `standalone`, `master`, or `node`. Set `"factor_on_managed_node": true` on a node only to factor that node's traffic alone, with the master not factoring the same clients.

## What This Patch Fixes

- PostgreSQL ticks no longer abort or deadlock when the panel writes traffic at the same moment, including the master's node traffic merge. A row the panel is writing is skipped and reported as `deferred`; its baseline stays unchanged and the next tick factors the full delta.
- A tick error that repeats is logged once, followed by `tick: recovered`.
- Auto backend detection matches the panel: only `XUI_DB_TYPE` selects PostgreSQL, a leftover `XUI_DB_DSN` on a SQLite panel is ignored, and a `database_dsn` in the config file takes precedence over the panel environment. Unknown `database_backend` values are rejected.
- URL DSNs without a host, such as `postgres://user:pass@/x-ui?host=/run/postgresql`, are printed with the password redacted.
- The installed systemd unit is identical to the packaged unit file.
- Overlapping persistent scopes audit a skipped enrollment once instead of on every tick.
- `unexclude` refreshes baselines from the current counters, so traffic from the excluded period is not factored.
- `pg_dump` backups honour quoted `sslmode` and `sslrootcert` values in keyword DSNs.

## Package Names

```text
xui-factor_v0.5.1-beta_linux_amd64.tar.gz
xui-factor_v0.5.1-beta_linux_arm64.tar.gz
```

Use the archive that matches the server architecture.

## Installation

```sh
tar -xzf xui-factor_v0.5.1-beta_linux_amd64.tar.gz
cd xui-factor_v0.5.1-beta_linux_amd64
sudo ./scripts/install.sh
```

Use `scripts/update.sh` from the extracted package when upgrading an existing installation. On systemd hosts, install enables and starts `xui-factor.service` by default, and update enables and restarts it by default.

## Upgrade Notes

- Upgrading from v0.5.0-beta needs no metadata migration and no reconcile run. `sudo ./scripts/update.sh` replaces the binary and the service unit and restarts the service.
- If XuiFactor is installed on a node, its ticks stop after the upgrade. Uninstall it there with `sudo ./scripts/uninstall.sh` and install it on the master. Factors already applied on the node stay in its counters and the master's.
- Panels on 3x-ui 2.x must be upgraded to 3.x first: stop `xui-factor.service`, upgrade 3x-ui, let the panel boot once, then install this release and run `xui-factor reconcile --dry-run` and `xui-factor reconcile`.
- If `/etc/xui-factor/config.json` contains a `database_dsn` with a password, restrict it with `sudo chmod 600 /etc/xui-factor/config.json`. New installs create the file with that mode.
- `traffic_applied` events no longer carry an `extra_all_time` field. Report totals are computed from `extra_up` and `extra_down`, which every release records, so existing events still count.

## Operator Checks

After installing or upgrading, run:

```sh
xui-factor doctor
xui-factor status
xui-factor report
xui-factor reconcile --dry-run
```

`doctor` prints the active backend. With the default `"database_backend": "auto"`, a PostgreSQL panel should report `backend: postgres` and a SQLite panel `backend: sqlite`.

## Behavior Notes

- Renaming a client in the panel keeps its traffic row but changes the email, and XuiFactor treats the result as a different client. Single-user rules for the old email are orphaned, excludes and overrides for the old email stop matching, and persistent scopes enroll the renamed client from its current counters after cleanup prunes the old tracking. Re-issue excludes and overrides for the new email.
- A client attached to several inbounds belongs to the first active rule or scope that enrolls it.

## Safety

- XuiFactor does not modify 3x-ui source code.
- Read-only commands such as `status`, `explain`, `report`, `audit`, `excludes`, and `overrides` open SQLite in read-only mode and PostgreSQL in a read-only session.
- Migrations, reconcile, and cleanup touch only XuiFactor metadata and never subtract previously factored traffic. The metadata schema version stays at 3.
- Installer and uninstall scripts preserve `/etc/x-ui/x-ui.db` and do not touch a PostgreSQL panel database.
