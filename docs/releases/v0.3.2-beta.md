# XuiFactor v0.3.2-beta

## Highlights

- Added exact-client override policies.
- Added `xui-factor override`, `xui-factor remove-override`, and `xui-factor overrides`.
- Overrides are stored with traffic id, inbound id, and email identity.
- Overrides win over single-user rules, inbound scopes, and global scopes.
- Excludes still win over overrides.
- Status shows active override counts and policy lines.

## Safety

- Override factors replace broader factors and do not stack with scope factors.
- Enabling, updating, or removing an override refreshes matching active baselines from current counters.
- Removing an override does not retroactively factor traffic from the override period.
- Cleanup can prune inactive override metadata after retention and never removes active overrides.

## Install

```sh
tar -xzf xui-factor_v0.3.2-beta_linux_amd64.tar.gz
cd xui-factor_v0.3.2-beta_linux_amd64
sudo ./scripts/update.sh
```

Use `install.sh` instead of `update.sh` for a first install.

## Example

Apply a broad factor, then assign one client a different future factor:

```sh
xui-factor enable-all --inbound-id 1 --factor 2
xui-factor override --email User --inbound-id 1 --factor 1.2
xui-factor overrides
```

Remove the override when the client should follow matching rules and scopes again:

```sh
xui-factor remove-override --email User --inbound-id 1
```
