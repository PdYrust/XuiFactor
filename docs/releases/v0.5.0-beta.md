# XuiFactor v0.5.0-beta

## Highlights

- Targets 3x-ui 3.x and follows its email-keyed client identity. Inbound scoped commands resolve membership through the panel `clients` and `client_inbounds` tables instead of the stale `client_traffics.inbound_id` pointer.
- Adds a PostgreSQL backend next to SQLite. A panel running PostgreSQL is detected automatically from the panel service environment file or its environment variables, and can also be configured explicitly with `database_backend` and `database_dsn`.
- Reconcile repairs metadata after a 3.x upgrade: rules re-link to a replaced traffic row by email, active excludes and overrides move onto the current row, and missing clients are revived when their row returns.
- Adds `pg_dump` backups on PostgreSQL, active backend reporting in `doctor`, and PostgreSQL integration coverage in CI.

## Package Names

```text
xui-factor_v0.5.0-beta_linux_amd64.tar.gz
xui-factor_v0.5.0-beta_linux_arm64.tar.gz
```

Use the archive that matches the server architecture.

## Install

```sh
tar -xzf xui-factor_v0.5.0-beta_linux_amd64.tar.gz
cd xui-factor_v0.5.0-beta_linux_amd64
sudo ./scripts/install.sh
```

Use `scripts/update.sh` from the extracted package when upgrading an existing installation. On systemd hosts, install enables and starts `xui-factor.service` by default, and update enables and restarts it by default.

## Upgrade Order

3x-ui must be upgraded first:

1. Stop `xui-factor.service`.
2. Upgrade 3x-ui and let the panel boot once so its database migration completes.
3. Install this release with `sudo ./scripts/update.sh`.
4. Run `xui-factor doctor`, then `xui-factor reconcile --dry-run` and `xui-factor reconcile`.

Legacy databases that still contain `client_traffics.all_time` are rejected with an upgrade hint until the panel migration has run.

## Operator Checks

After installing or upgrading, run:

```sh
xui-factor doctor
xui-factor status
xui-factor report
xui-factor reconcile --dry-run
xui-factor cleanup --dry-run
```

Use `systemctl status xui-factor.service --no-pager` to confirm daemon state on systemd hosts.

## PostgreSQL

Set the backend in `/etc/xui-factor/config.json`:

```json
{
  "database_backend": "postgres",
  "database_dsn": "postgres://x-ui:password@127.0.0.1:5432/x-ui?sslmode=disable"
}
```

Keep the default `auto` backend and XuiFactor reads `XUI_DB_TYPE` and `XUI_DB_DSN` from the panel service environment file directly (`/etc/default/x-ui`, `/etc/conf.d/x-ui`, or `/etc/sysconfig/x-ui`), so the daemon and one-off commands detect a PostgreSQL panel without extra configuration; process environment variables win over the file, and explicit config file values win over both. `xui-factor doctor` prints the active backend, redacts the DSN password, and probes write access. On PostgreSQL, `xui-factor backup` requires `pg_dump` and writes `.dump` files that restore with `pg_restore`.

## Policy Model

XuiFactor resolves one effective decision per client:

```text
exclude > override > single-user rule > inbound scope > global scope
```

Disabling rules or removing policies does not revert previously factored traffic. Removing an exclude or override resumes future matching from current counters and does not retroactively factor earlier traffic. Excludes and overrides are tied to the client and stay effective when it moves between inbounds.

## Behavior Notes

- A client belongs to one shared traffic row per email; factors apply to the client across every inbound it is attached to.
- Inbound pointer drift (`client_traffics.inbound_id` moving between inbounds) is adopted instead of marking rules missing.
- When the panel replaces the email-keyed traffic row (upgrade merge or rename), reconcile and the next tick move rules, excludes, and overrides onto the current row; re-issued policies update the moved row instead of duplicating.

## Safety

- XuiFactor does not modify 3x-ui source code.
- XuiFactor metadata lives in `xui_factor_*` tables (metadata schema version 3). The migration drops obsolete baseline columns and retires duplicate active policies.
- Read-only commands such as `status`, `explain`, `report`, `audit`, and `doctor` do not modify traffic counters.
- Migrations, reconcile, and cleanup touch only XuiFactor metadata and never subtract previously factored traffic.
- Installer and uninstall scripts preserve `/etc/x-ui/x-ui.db`.
- Builds require Go 1.25 or newer.
